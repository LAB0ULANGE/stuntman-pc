## Le clignotement du menu

Le menu (et les autres : chargement, carrière, filmographie) dessine chaque
trame dans son propre tampon : les trames paires dans le tampon à 0, les
impaires dans celui à 50. Le tampon à 0 est vu par le GPU sous trois
largeurs (512, 640 et 1024) ; le jeu dessine dans plusieurs, et dessiner
dans l'une marque les autres « périmées » jusqu'à leur prochain dessin.

La présentation ne prenait que l'image GPU à jour : une trame sur deux
(le tampon à 0, périmé) partait vers l'image du GS logiciel, c'est-à-dire la
mémoire sans ce que le GPU avait dessiné. L'écran alternait 25 fois par
seconde entre le vrai menu et une image ancienne ou incomplète.

Trouvé avec un traceur ajouté pour l'occasion (`PS2HOST_FIELD_TRACE=1` :
chaque trame, son tampon, sa parité, neuve ou non, tissée ou non, et
pourquoi elle part vers l'image logicielle).

Réparation (`display_reload=on`) : avant de montrer une image périmée, elle
est remise à jour depuis la mémoire comme le ferait le prochain dessin.
Toutes les trames du menu passent maintenant par l'image GPU.

## Le désentrelacement auto, revu

En temps réel le menu rate des trames (il tient une image 3 trames, parfois
6 quand il lit sa vidéo sur le disque), toujours en gardant l'ordre des
parités. L'ancien `auto` passait alors en image seule puis revenait au
tissage : la hauteur de l'image changeait sans arrêt. Maintenant : une
trame va dans l'image tissée seulement si elle est neuve (sur les lignes de
sa parité), et l'image tissée est montrée tant que les trois dernières
images neuves ont alterné de parité. Sinon, l'image seule.

| endroit (temps réel, fenêtre) | trames tissées | trames sur l'image logicielle |
| --- | --- | --- |
| menu principal 7200-7800, avant | 70-96 % | ~50 % |
| menu principal, après | 100 % | 0 |
| chargement, carrière, filmographie (ta carte) 7000-10300 | 100 % | 0 |
| cascade 11300-12800 | 0 % (image seule) | 0 |
